# 统计面板统一设计方案（成员运力并入统计面板）

> 状态：已实施（2026-09-07，commits e669239/05e5b8e/e36b9be，门禁全绿：176 单测 + 23 e2e；2026-09-07 文档整理时移入 archived/，未等发版）。纯前端展示层重组，不动数据层、接口与统计口径。
>
> 评审决议（2026-09-07）：① 三方占比**双呈现**——StatsBar 速览迷你条保留，面板「来源」页签放同口径明细；② 负责人行内 📦 连击徽标**顺手做**。

## 背景与问题

看板页现有三处统计展示，语义重复、可见性策略互相矛盾：

| 模块                               | 位置     | 可见性   | 内容                                                    | 切片维度                   |
| ---------------------------------- | -------- | -------- | ------------------------------------------------------- | -------------------------- |
| 统计条 StatsBar                    | 表格上方 | 常驻     | 健康度指标 + 三方占比迷你条 + 徽章 + 指纹 + 操作按钮    | 班次整体 + 来源            |
| 成员运力（BoardPage 内联 section） | 表格下方 | 常驻     | 每人 capacity / assigned / 件数 / 送达 / 滞留、超载提示 | 负责人                     |
| 统计面板 StatsPanel（`<details>`） | 页面底部 | 默认折叠 | 提出人记分卡 / 稀有度通胀 / 滞留原因瀑布                | 提出人 / 稀有度 / 结转原因 |

问题本质：**成员运力与统计面板是同一种东西**——同一批快件按不同维度分组聚合。成员运力的 done/carriedIn 与记分卡的 delivered/stranded 是平行概念，只是一个按负责人切、一个按提出人切。此外：

- 成员运力（装载时看余量，周中高频）常驻，复盘统计（周五低频）折叠——可见性策略没错，但被切成两张卡片后，「按人看统计」有两个入口；
- StatsBar 塞了约 10 类信息（指标 + 占比 + 徽章 + 指纹 + 操作按钮），职责过载。

## 业界参考（2026-09-07 调研）

1. **Linear Insights 的 Measure × Slice 模式**（linear.app/docs/insights）：同一批 issue，选一个度量（件数/工时）、一个切片维度（assignee / priority / status…），图和表随切片切换——**同一布局、不同数据**。本项目五组统计正是这个结构：负责人 / 提出人 / 稀有度 / 结转原因 / 来源。
2. **NN/g《Tabs, Used Right》**（nngroup.com/articles/tabs-used-right）：页签适用判据——内容有少量清晰分组、**各页签同构布局不同数据**、非默认页签是补充性内容（默认页签获得注意力）、用户无需并排对比多个页签。本面板五维全部命中；且「非默认页签是补充性」恰好匹配 v2.0 隐形预算哲学（复盘维度不该抢日常注意力）。
3. **NN/g 手风琴研究**（nngroup.com/articles/accordions-on-desktop）：折叠降低可见性、增加交互成本，**关键信息不应藏在折叠面板里**——运力/超载是操作伴随信息，不该跟着进折叠。
4. **运力可视化标准形**（业界一致做法）：每人一条「已装 / 上限」进度条，超载变红——
   - Azure DevOps Sprint Capacity 面板（及社区复刻 ado-capacity-widget）：per-person bars，remaining > capacity 红条；
   - shadcn team-workload-overview block：utilization 进度条 + 件数徽标 + 团队合计；
   - Baytek Agile Analytics「Sprint Capacity」：committed-points vs assignee capacity 每人分解。
     现状纯文本行「已装 x 点 · N 件 · 送达 y · 滞留 z」是这些案例的退化形式。

## 设计决策

### 1. 统一骨架：一张卡片 + 维度页签

原「成员运力」section 与 StatsPanel 合并为**一张常驻 glass-card**，位置在表格正下方（现成员运力位置）。卡头一行 segmented 切换：

```
统计   [ 负责人 ] [ 提出人 ] [ 稀有度 ] [ 结转原因 ] [ 来源 ]
──────────────────────────────────────────────────────────
张三   ▓▓▓▓▓▓▓▓░░░░  8/10 点    3 件 · 送达 2 · 滞留 1
李四   ▓▓▓▓▓▓▓▓▓▓▓▓▓  13/10 点  4 件 · 送达 1 · 滞留 0  （超载）
...
```

每个维度共用同一行式骨架：**维度值标签（定宽）+ 主条形（flex）+ 数字徽标组**。主条语义按维度定义：

| 页签           | 主条                                    | 数字组                                           | 备注                               |
| -------------- | --------------------------------------- | ------------------------------------------------ | ---------------------------------- |
| 负责人（默认） | 运力条 assigned/capacity，超载整条变红  | N 件 · 送达 x · 滞留 y                           | 替代纯文本行，参考 ADO/shadcn      |
| 提出人         | 送达/提出比条（**签收口径**）           | 提出 x · 送达 y · 滞留 z · UR+SSR p% · 在车 v 班 | 即记分卡换形，数字全保留           |
| 稀有度         | 滞留/总数条（暴露通胀：滞留越多条越高） | 总数 x · 送达 y · 滞留 z                         | 底注保留「UR vs N 滞留率」通胀判读 |
| 结转原因       | count/max 条（现瀑布原样）              | x                                                | 空态文案保留                       |
| 来源           | 该来源占比条                            | x 件 · p%                                        | 自 StatsBar 迁入（见决策 3）       |

现有口径注脚（「三方占比与来源自 v2.0 起采集…记分卡送达为签收口径…」）保留在面板底部。**口径连续性决议不受影响**：滞留率/完成率 v1 口径、记分卡签收口径、昨日天气与徽章 done 口径，全部原样。

### 2. 可见性：常驻 + 页签，不折叠

- 运力可见性**不降级**（现状常驻，合并后仍常驻，无功能回退）；
- 复盘维度从「details 展开」变「点页签」，一击可达反而更快；默认视图只显示运力，其余维度不占纵向空间也不主动展示——**隐形预算哲学保留**（v2 统计不制造日常 KPI 压力的本质是「默认不见」，页签同样满足，且比折叠少一层卡片堆叠）；
- 页面纵向高度与现状基本持平：现状 = 成员运力卡（N 行）+ 折叠面板头一行；新 = 页签行一行 + 负责人视图 N 行。

### 3. 三方占比双呈现（评审拍板）

- StatsBar 迷你条**原样保留**（周中速览，一屏内随手看结构）；
- 面板新增「来源」页签，放同口径明细（逐来源占比条 + 件数 + 百分比）；
- StatsBar 职责维持「本班健康度速览 + 快捷操作」不动。

### 4. 不做的东西

- **不动数据层**：`weeklyStats` 已一次返回 members/requester/inflation/source/carryReasons，纯前端重组，无新端点、无 schema 改动、无审计变化；
- 不给面板加班次对比、趋势图、导出等（无诉求，拒绝投机性功能）；
- **不动 StatsBar 的任何内容**（指标、三方占比迷你条、徽章、指纹、按钮全部原样；toast 逻辑不动）。

补充（2026-09-07，实施前发现）：成员删除功能已先行落地，入口在成员运力区行内「删除」按钮——统一后该入口**随负责人视图原样迁入面板**（确认弹窗、守卫错误提示、「我是谁」联动清空全部不变），e2e `board.spec.ts` 成员删除用例按「section 含『成员运力』文本 + li 行 + 行内删除按钮」定位，新结构保持这三点即零改动兼容。连击徽标按评审决议放进负责人行（`badges.streaks` 数据已有）。
