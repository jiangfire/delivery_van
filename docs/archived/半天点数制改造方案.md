# 半天点数制改造方案

> 状态：已完成并归档（vitest 95 项、tsc、eslint、prettier、Playwright 15 项全绿；真实库副本冒烟验证迁移幂等）。

## 目标

任务体量从「三档粒度（1/3/5 天）」改为「半天点数制」：**1 点 = 半天，10 点 = 五天**。点数取 1~10 任意整数（半点步进），成员运力同步改为点数口径。

## 决策（已与需求方确认）

- 取值：1~10 任意整数，服务端 zod 强制（拒绝 0、11、非整数）。
- 单位：任务档位与成员运力**全部用「点」**展示；成员运力默认 10 点/周（=5 天），上限 14 点。
- 存量迁移：`ensureSchema` 启动时幂等迁移——任务 size 旧三档 1/3/5（天）×2 变 2/6/10（点），成员运力 ≤7 天 ×2；用 `PRAGMA user_version` 作迁移标记，保证只执行一次（新库表为空，UPDATE 为 no-op）。

## 改动点

| 位置                      | 改动                                                                                           |
| ------------------------- | ---------------------------------------------------------------------------------------------- |
| `api/vanRouter.ts`        | `sizeTier` 改为 `z.number().int().min(1).max(10)`；成员 capacity 上限 7→14、默认 5→10          |
| `api/queries/van.ts`      | `size?: 1\|3\|5\|null` 类型改为 `number \| null`（addTask / updateTask 两处）                  |
| `api/ensureSchema.ts`     | 新增 user_version 门控的存量迁移（size ×2、capacity ×2）                                       |
| `src/pages/BoardPage.tsx` | 档位编辑器选项 1~10；徽标文字「N 点」；颜色按点数分桶（≤2 蓝 / ≤6 橙 / 其余红）；运力文案天→点 |
| `e2e/board.spec.ts`       | 「档位仅 1/3/5 三档可选」用例改为 1~10 点数制                                                  |
| 文档                      | 设计方案、README、AGENTS.md、发版计划中三档粒度相关描述同步更新                                |

## 测试

- `api/vanRouter.test.ts`：点数 schema 接受 1~10（含 2 等偶数），拒绝 0 / 11 / 1.5。
- `api/ensureSchema.test.ts`：内存库跑真实 `ensureSchema`，验证旧值 ×2、重复启动不重复翻倍、迁移后新写入的点数不被误翻倍。
- e2e：下拉出现 1~10 选项，选 7 显示「7 点」。
