# 任务大厅与稀有度分级设计方案（已在 v1.0 全量实施）

> 定位：本方案已定稿并随 v1.0「niulai」落地，本文档作为设计依据存档。
> 要点：稀有度 = 价值/优先度/工作量三位一体，凭直觉定级；整体文字着色呈现（神话级彩虹动画），颜色只是标记不做筛选；挂账轮数逐条显示；不做奖励但要统计；无权限看板模式。

## 一、概念模型

```
任务大厅（Hall）          班次（Van）            成员（Courier）
┌──────────────┐   接取   ┌──────────────┐  承运  ┌──────────┐
│ 委托（Quest）│ ──────→ │ 快件（Task） │ ─────→ │ 永久标签  │
│ 带稀有度成色  │         │ 带 1/3/5 档位 │        │          │
└──────────────┘         └──────────────┘        └──────────┘
```

- **委托**：大厅里挂出来的工作条目，业务语言描述，带稀有度成色。委托可以没人接、挂着等。
- **接取**：从大厅把委托装上某班车的动作 = 创建一条关联该委托的快件。委托本身不进周表，上车的是快件。
- **无权限看板**：工具没有用户体系，任何人都能改任何条目。这是刻意的——小团队靠公开透明自治，看板就是唯一事实源，权限是规模上来之后才需要考虑的事。稀有度的定级、调整、接取都靠发车会上的现场对齐，不靠系统锁。

## 二、稀有度：一个标签读三件事

稀有度是**综合价值度标签**，一眼同时读出：这单**值不值钱**（价值）、**急不急**（优先度）、**大不大**（预期工作量）。三者不拆开打分——拆开就是三套争论，合成一档才有游戏感，也才符合本工具「粗粒度是故意的设计」的一贯原则。

| 稀有度 | 色  | 综合含义（价值 / 优先度 / 工作量） | 上车规则                                                 |
| ------ | --- | ---------------------------------- | -------------------------------------------------------- |
| 普通   | 白  | 日常杂活 / 不急 / 小               | 可直接上车                                               |
| 优秀   | 绿  | 常规迭代 / 正常排 / 中小           | 可直接上车                                               |
| 稀有   | 蓝  | 重要功能、关键客户诉求 / 优先 / 中 | 可直接上车                                               |
| 史诗   | 紫  | 季度级重点 / 高优先 / 大           | 可直接上车，发车会优先过                                 |
| 传说   | 橙  | 跨季度战略 / 最高优先 / 很大       | 可直接上车，建议先切探针任务                             |
| 神话   | 彩  | 愿景级 / 不确定 / 切不动           | 可直接上车（稀有度只是标记，切片是会上纪律，系统不拦截） |

- 稀有度由录入人**凭直觉**定，不设计任何评分、计算或校验规则；发车会上任何人可质疑调整（与档位质疑同一机制）。
- 与快件档位的关系：稀有度里的「工作量」是**直觉预期**，快件的 1/3/5 档位是**上车时的承诺**。高稀有度委托切出来的快件往往占大档位，普通杂活一般 1 天档——两者互相印证，估偏了周五复盘校准。
- 「神话必须切片」是发车会纪律，系统不拦截——稀有度只是标记，任何稀有度的委托都可直接上车（v1.0 终审时明确解除拦截）。

## 三、呈现：整体文字着色，颜色只是标记

- 大厅条目**整条文字按稀有度着色**：普通=默认正文色，优秀/稀有/史诗/传说用对应色，**神话级要花里胡哨**——彩虹渐变 + 流动动画（`bg-clip-text` + keyframes 位移渐变），它是大厅里的传说生物，就该一眼扎眼。
- **颜色只是标记，不做任何延伸功能**：不做按稀有度的筛选、排序、分组，不为颜色配快捷键或规则。看板扫一眼就知道成色，仅此而已。
- 周任务表「所属委托」列的委托标题同样着色，这班车装了多少高价值的货直接可看。
- 常规配色走 Tailwind 调色板（green-600 / blue-600 / purple-600 / orange-500 等），保证浅色背景下可读；普通级无颜色（默认正文色）本身就是最低档的表达。
- **挂账轮数逐条显示**：每条待接取委托标注「挂 N 轮」（挂出后又发了几班车），接取上车后不再显示。这是硬要求——委托挂了几轮没人接，是发车会必须一眼看到的事，不允许藏进统计页。

## 四、统计：不带奖励，但要可数

委托**不做任何奖励/积分机制**（与设计文档「指标不挂钩绩效」的纪律一致），但稀有度数据必须沉淀下来用于复盘：

- 统计条加「本班稀有度构成」（如 紫 1/2 · 蓝 2/3，含义 送达/总数），回答「这班车装的是不是重要的货」。
- 周统计按稀有度分桶看送达率：高稀有度件频繁滞留 = 战略项目在被杂活挤占，这正是发车会该暴露的问题。
- 大厅挂账轮数（见上节）是最低成本的滞留信号；聚合口径（如大厅平均挂账轮数）可后续再议。

## 五、落地说明

- `pool_items.type`（epic/ready）→ `pool_items.rarity`（common/uncommon/rare/epic/legendary/mythic，默认 common）。发版前无存量数据，CREATE 语句直接改，无迁移负担。
- 挂账轮数：`pool_items.posted_van` 记录挂出时班次，轮数 = vans 表中晚于它创建的班次数；非待接取状态恒为 0。
- 班次模型同期重构：班次不再绑定周五，由「发新车」手动创建，字母放开 A–Z；新增 `vans` 表记录已发班次。

## 七、评审结论（已定，无待定项）

- 稀有度 = 价值/优先度/工作量三位一体，一个标签，凭直觉定级，不拆分打分。
- 呈现用整体文字着色，不做徽标；颜色只是标记，不做筛选/排序/分组。
- 神话级配色要花里胡哨（彩虹渐变动画）。
- 挂账轮数逐条显示，接取清零。
- 不做奖励/积分，但稀有度参与统计。
- 无用户无权限，谁都能改，大厅是看板不是流程系统。
