# 稀有度分级设计方案（v1.0 六级 → 五级重构）

> 本文由两份历史文档合并而成：原《任务大厅与稀有度分级设计方案》（v1.0 六级，`common/uncommon/rare/epic/legendary/mythic`，中文标签）与原《稀有度五级重构方案》（2026-08-22 实施，五级 `n/r/sr/ssr/ur`，英文缩写）。前者讲**稀有度为何这样设计**，后者讲**为何从六级改为五级**，同属一件事的两代，故合并；正文保留原始结论，不改写。
> 状态：**两级均已实施完成**。五级重构门禁全绿（单测 76 例含迁移映射 3 例、E2E 14 例、tsc / eslint / prettier 通过；旧库迁移经真实冒烟验证，六级存量 → `n/r/sr/ssr/ur/ur`，二次启动幂等）。

## 一、设计理念：稀有度是一个标签读三件事

> 本节来自六级时期方案，讲的是**稀有度的本质**，五级重构未改动这层，只改了级数与呈现。至今有效。

稀有度是**综合价值度标签**，一眼同时读出：这单**值不值钱**（价值）、**急不急**（优先度）、**大不大**（预期工作量）。三者不拆开打分——拆开就是三套争论，合成一档才有游戏感，也才符合本工具「粗粒度是故意的设计」的一贯原则。

| 六级（v1.0 原始） | 色  | 综合含义（价值 / 优先度 / 工作量） | 上车规则                                                 |
| ----------------- | --- | ---------------------------------- | -------------------------------------------------------- |
| 普通 common       | 白  | 日常杂活 / 不急 / 小               | 可直接上车                                               |
| 优秀 uncommon     | 绿  | 常规迭代 / 正常排 / 中小           | 可直接上车                                               |
| 稀有 rare         | 蓝  | 重要功能、关键客户诉求 / 优先 / 中 | 可直接上车                                               |
| 史诗 epic         | 紫  | 季度级重点 / 高优先 / 大           | 可直接上车，发车会优先过                                 |
| 传说 legendary    | 橙  | 跨季度战略 / 最高优先 / 很大       | 可直接上车，建议先切探针任务                             |
| 神话 mythic       | 彩  | 愿景级 / 不确定 / 切不动           | 可直接上车（稀有度只是标记，切片是会上纪律，系统不拦截） |

- 稀有度由录入人**凭直觉**定，不设计任何评分、计算或校验规则；发车会上任何人可质疑调整（与点数质疑同一机制）。
- 与快件点数的关系：稀有度里的「工作量」是**直觉预期**，快件的半天点数（1~10 点，1 点 = 半天）是**上车时的承诺**。高稀有度委托切出来的快件往往占大点数，普通杂活一般 1 点——两者互相印证，估偏了周五复盘校准。
- 「神话必须切片」是发车会纪律，系统不拦截——稀有度只是标记，任何稀有度的委托都可直接上车（v1.0 终审时明确解除拦截）。

### 已废弃：任务大厅 / 委托两层模型

六级方案成文于「任务大厅」尚存的年代，其概念模型为**委托（Quest）→ 接取 → 快件（Task）**两层，并有独立的挂账轮数机制：

```
任务大厅（Hall）          班次（Van）            成员（Courier）
┌──────────────┐   接取   ┌──────────────┐  承运  ┌──────────┐
│ 委托（Quest）│ ──────→ │ 快件（Task） │ ─────→ │ 永久标签  │
│ 带稀有度成色  │         │ 带 1/3/5 档位 │        │          │
└──────────────┘         └──────────────┘        └──────────┘
```

> ⚠️ **该模型已废弃**：现行架构是「**快件即一切**」——工作条目只有 `tasks` 表一种，直接携带稀有度与提出人；旧「任务大厅」（`pool_items` 表）表结构保留但**不读写**（见 `AGENTS.md`）。委托合并进主表格后，"接取"动作与"挂账轮数"随之失去载体。
> **保留下来的**：委托层的**无权限看板立场**仍然有效且是本项目零鉴权的设计根源——"工具没有用户体系，任何人都能改任何条目，这是刻意的：小团队靠公开透明自治，看板就是唯一事实源，权限是规模上来之后才需要考虑的事。稀有度的定级、调整都靠发车会上的现场对齐，不靠系统锁。"

## 二、五级重构（现行，2026-08-22 实施）

### 2.1 为什么改

六级粒度过细、辨识成本高，且顶级两档（传说 / 神话）几乎无差别。本次重构：

- **六级 → 五级**，命名改为抽卡风格的英文缩写：**N / R / SR / SSR / UR**；
- **展示全部改用英文缩写**，不再显示中文标签；
- 样式五档：**普通样式 / 绿色 / 蓝色 / 紫色 / 彩色（彩虹动画）**；
- 依旧只是标记：标题与稀有度列文字着色、UR 彩虹动画，**不做任何校验与上车拦截**（核心业务规则不变）。

### 2.2 新旧对照与迁移映射

| 旧值（六级） | 新值（五级） | 显示 | 样式           | 实现                         |
| ------------ | ------------ | ---- | -------------- | ---------------------------- |
| common       | `n`          | N    | 普通（默认色） | 无类名                       |
| uncommon     | `r`          | R    | 绿色           | `text-emerald-600`           |
| rare         | `sr`         | SR   | 蓝色           | `text-sky-600`               |
| epic         | `ssr`        | SSR  | 紫色           | `text-violet-600`            |
| legendary    | `ur`         | UR   | 彩色           | `rarity-ur-text`（彩虹动画） |
| mythic       | `ur`         | UR   | 彩色           | 同上                         |

关键取舍：

1. **存储值用小写** `n/r/sr/ssr/ur`，与库内既有枚举风格一致（status 用 todo/doing/done/carried）；显示层统一大写（`toUpperCase()`），无需再维护中文标签映射。
2. **legendary 与 mythic 合并为 UR**：两个顶档语义重叠，映射时一对一保序优先（common→n … epic→ssr），最高两档归并到 UR。旧六档中的琥珀色（legendary）随之移除。
3. 新增快件的**默认稀有度 = N**（原 common），zod default、`addTask` 兜底、编辑器 initial 三处同步。

### 2.3 存量数据迁移

与「启动时幂等建表」同一模式：在 `api/ensureSchema.ts` 内追加一组幂等 `UPDATE`，启动时自动完成，重复执行无副作用（旧值迁移后不再存在）：

```sql
UPDATE tasks SET rarity='n'  WHERE rarity='common';
UPDATE tasks SET rarity='r'  WHERE rarity='uncommon';
UPDATE tasks SET rarity='sr' WHERE rarity='rare';
UPDATE tasks SET rarity='ssr' WHERE rarity='epic';
UPDATE tasks SET rarity='ur'  WHERE rarity IN ('legendary','mythic');
```

- 迁移映射以常量 `LEGACY_RARITY_TO` 定义在 `db/schema.ts`（新旧值域同处可见），`ensureSchema` 据此生成 UPDATE，配套单测校验映射完整性（旧六级全覆盖、目标值都在新五级内）。
- **`pool_items` 为废弃表，不做数据迁移**：`poolItems.rarity` 的 Drizzle 类型放宽为纯 `text`（去掉 enum 收窄），历史旧值原样保留，反正无人读写。
- 建表 SQL 中 rarity 的 `DEFAULT 'common'` 同步改为 `DEFAULT 'n'`；旧库已加列的 default 残留无影响（Drizzle insert 显式写值，default 不生效）。

## 三、呈现与统计纪律（源自六级方案，五级未改）

> 本节结论**至今有效**，仅"神话"对应现 "UR"。

- **颜色只是标记，不做任何延伸功能**：不做按稀有度的筛选、排序、分组，不为颜色配快捷键或规则。看板扫一眼就知道成色，仅此而已。
- **整体文字着色呈现**：普通级无颜色（默认正文色）本身就是最低档的表达；最高档要花里胡哨——彩虹渐变 + 流动动画（`bg-clip-text` + keyframes 位移渐变，`.rarity-ur-text`），它就该一眼扎眼。
- **不做奖励 / 积分机制**（与"指标不挂钩绩效"的纪律一致），但稀有度数据必须沉淀下来用于复盘：
  - 统计条加「本班稀有度构成」（含义 送达 / 总数），回答"这班车装的是不是重要的货"；
  - 按稀有度分桶看送达率：高稀有度件频繁滞留 = 战略项目在被杂活挤占，这正是发车会该暴露的问题。
- 常规配色走 Tailwind 调色板，保证浅色背景下可读。

> 已随两层模型废弃：**挂账轮数逐条显示**（"每条待接取委托标注「挂 N 轮」"）——委托并入主表格后失去载体。

## 四、明确不做

- 不引入稀有度筛选、排序权重、上车拦截等任何校验逻辑（维持「只是标记」）；
- 不迁移 `pool_items` 废弃表数据；
- 不动版本号（属 v1.0 内迭代）；
- 不做奖励 / 积分，积分永不兑换现金、永不进绩效考评。

## 五、评审结论（v1.0 终审，已定，无待定项）

- 稀有度 = 价值 / 优先度 / 工作量三位一体，一个标签，凭直觉定级，不拆分打分。
- 呈现用整体文字着色，不做徽标；颜色只是标记，不做筛选 / 排序 / 分组。
- 最高档配色要花里胡哨（彩虹渐变动画）。
- 不做奖励 / 积分，但稀有度参与统计。
- 无用户无权限，谁都能改，看板是唯一事实源不是流程系统。
