## 三、必修问题（建议发版前修）

### 1. 提出人无法清空（功能 bug，已复现）✅已修复

- **现象**：快件已有提出人时，在提出人面板点「无」，toast 报错、值回滚，无法清空。
- **根因**：前端把空值转成 `null` 发送，但 update 接口的 zod 校验只写了 `optional()` 没有 `nullable()`。zod v4 中 `optional` 只接受 `undefined`，不接受 `null`。
- **复现证据**（临时库上直调 tRPC）：`update({ id, requester: null })` → `BAD_REQUEST: Invalid input: expected string, received null`；`note` / `acceptance` 都写了 `.nullable().optional()`，唯独 `requester` 漏了。
- **为何测试没拦住**：e2e「提出人可修改并保存」只验证面板能关闭，没断言清空后的持久化。
- **决策与处理**：修复。`api/vanRouter.ts` requester 补 `.nullable()`；新增 e2e「提出人可清空并持久化（选『无』）」回归用例。

### 2. CI 的 E2E 有时区时间炸弹（CI 稳定性）✅已修复

- **现象**：在 GitHub Actions 上，**每天 UTC 16:00–24:00（北京时间凌晨 0–8 点）推送，e2e「置完成自动记送达日期」必挂**。
- **根因**：服务端 `todayStr()` 固定转上海时区，而断言用的 `e2e/helpers.ts` `todayStr()` 取测试进程本地时区；`playwright.config.ts` 没设 `timezone`，GitHub runner 是 UTC。
- **为何至今没炸**：历史推送都在 UTC 0–10 点（北京白天）。查 CI 历史：8-21 的两次失败都在时区窗口外，是修 bug 期间的真实失败，与本问题无关。
- **决策与处理**：修复。`playwright.config.ts` 的 `use` 加 `timezone: "Asia/Shanghai"`，与服务端同口径。

## 四、建议修（低成本防御/清理）

### 3. 成员名含半角逗号会静默破坏负责人聚合 ✅已修复

- **问题**：`listTasksByVan` 用 `group_concat` + `split(",")` 还原负责人标签，而成员名与 owners 的 zod 校验都不禁逗号。名字带半角 `,` 的成员会导致标签错拆、运力统计永远匹配不上（静默数据损坏）。
- **决策与处理**：修复。`api/vanRouter.ts` 新增导出的 `memberTag` 校验（trim 后 1~64 字符、拒绝半角逗号），members.add 与 tasks.add/update 的 owners 统一复用；前端 MultiSelectEditor / RequesterSelect 的「新增成员」输入同步拦截；新增 `api/vanRouter.test.ts` 覆盖（含全角逗号可用的边界）。

### 4. 死代码：`src/components/TagEditorInner.tsx`（137 行）✅已删除

- **问题**：全项目无任何引用，是旧版标签编辑器遗留。
- **决策与处理**：删除。

### 5. eslint warning：BoardPage columnDefs deps 数组冗余 ✅已修复

- **问题**：`columnDefs` 的 useMemo 同时依赖 `memberNamesKey` 和 `memberNames`，前者被 eslint 判定多余；且「按内容记忆」机制因 `memberNames` 也在 deps 里实际未生效。
- **决策与处理**：删掉 `memberNamesKey` 及过时注释，注释改为说明 react-query structural sharing 的引用稳定性，lint 归零。

## 五、需要决策的一项

### 6. 班次编码跨月语义：文档口径与实现不一致 ✅已按人工决策修复（改代码）

- **文档说**（AGENTS.md / README / `contracts/vans.ts` 注释）：「字母 = 当月第几班车」「班次归属创建时所在的月份」。
- **评审时实现是**：`dispatchVan` 从最新班编码 +1，**Z 才换月**——周度团队每月 4-5 班，跨月后新班次会继续用旧月份编码（7 月 A–E，8 月的新车是 `DV2607F`），编码月份失真。
- **评审原建议**：改文档不改代码（担心动 `carryOver` 的紧邻校验）。**人工决策纠正：每个月都从 A 开始，改代码**。
- **处理**（保持结转自洽的完整实现）：
  - `contracts/vans.ts` 新增 `nextVanCodeFrom(code, today)`（跨月感知的下一班）与 `carryTargetCode(fromVan, existingVans, today)`（结转目标：已存在的最近一班优先，否则按日期推导）；
  - `dispatchVan` 跨月发新车从新月份 A 重新计数；`carryOver` 改用 `carryTargetCode` 校验目标，与前端结转按钮同口径；
  - 测试：contracts 新增 7 个用例（跨月/跨年/Z 边界/结转目标三分支），mock 测试补跨月发车、既有班结转、并发幂等；
  - 文档同步：AGENTS.md、README、`contracts/vans.ts` 头注释改为「编码锚定创建时所在月份，每个自然月从 A 重新计数」。
  - 兼容性核对：开发库存量班次 DV2608A/B/C 均在当月，新规则下下一次发车仍为 DV2608D，无冲突。
