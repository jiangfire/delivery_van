# v1.0「niulai」发版计划

> 关联文档：`docs/周度发车机制设计方案.md`（业务机制）、`docs/v1.0-niulai-评审决策存档.md`（评审结论）、`docs/任务大厅与稀有度分级设计方案.md`（后续版本方向）。
> 数据库尚在发版前阶段，**无存量数据兼容负担**，schema 调整自由。

## 一、版本范围

v1.0 交付一个可投入试运行（设计方案第九章程四周路径）的完整工具：

- **班次体系**：DV 编码班次、班次切换 + 快速跳转、跨月跨年边界正确
- **周任务表**：AG Grid 行内编辑、三档粒度（1/3/5 天）服务端强制、送达二值化 + 送达日期可补录、行内删除
- **成员产能**：成员为永久标签（不可删除）、运力失焦编辑、调低运力回检已排峰值、超载服务端拒单、产能速览统计
- **任务大厅**：委托录入/编辑/删除、三态由任务自动推导（`syncPoolStatus`）、Epic 不可上车、可解除关联
- **滞留结转**：一键转下一班（仅允许紧邻班次）、事务包裹 + 幂等防重、≥2 班强制复盘提示
- **统计条**：未送达 X / 共 Y、送达率、滞留率、强制复盘数（设计方案第八章三指标之二；估偏率靠备注 + 复盘定性）

明确不做（与设计方案对齐）：无账号无权限（谁都能改的看板）、无绩效挂钩、无精确工时、无故事点。

## 二、质量门禁与 CI

- 本地门禁：`npm test`（28 用例）、`npm run check`、`npm run lint`、`npx prettier --check .`，提交前必跑。
- **GitHub Actions**（`.github/workflows/ci.yml`，push/PR 触发）：
  - `check` job：prettier --check → eslint → tsc → vitest
  - `docker` job：`docker build` + 容器冒烟（首页 200、`/api/trpc/ping` 返回 ok）——本机无 Docker 环境，镜像构建正确性由 CI 保证。

## 三、发版步骤

1. [ ] 确认 main 上 CI 全绿（check + docker 两个 job）
2. [ ] `npm run dev` 人工过一遍核心动线：录委托 → 装车（双击编辑，关联委托/负责人/档位）→ 超载拒单 → 打勾送达 → 滞留转下一班 → 班次跳转
3. [ ] 打 tag：`git tag v1.0.0 && git push --tags`
4. [ ] 部署：`docker build -t delivery_van . && docker run -p 3000:3000 -v delivery_van_data:/app/data delivery_van`（**必须挂数据卷**，见 README）
5. [ ] 按设计方案附录「第一周启动检查单」启动试运行：录成员（或 `npm run db:seed` 后改）、PM 周四前把委托写进大厅、宣布三条纪律（>5 天不上车 / 完成只看二值 / 指标不挂钩绩效）

## 四、发版验收标准

- CI 两 job 全绿；容器首次启动自动建表、重启数据不丢（数据卷验证）
- 第一周试运行结束能回答：「每个人是否都清楚自己下周要干什么？」

## 五、发版后路线（详见各方案文档）

- **v1.1**：任务大厅稀有度体系——rarity 字段与数据迁移、整体文字着色（神话级彩虹动画）、挂账轮数逐条显示、接取按钮
- **v1.2**：稀有度构成统计、按稀有度分桶送达率
- **待定**：班次模型「淡化周概念」重构（单月多班车）；`db:seed` 对全新库自愈（先调 `ensureSchema`）
