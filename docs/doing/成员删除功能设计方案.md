# 成员删除功能设计方案

> 状态：进行中（2026-09-07 立项）。本功能推翻既有设计决策「成员是永久标签，不可删除」，按本方案修订。

## 背景与决策

- 现状：成员唯一入口是表格编辑器里的「即时新增标签」，**手滑加错名字后没有任何删除手段**。
- 既有设计（README / AGENTS.md / 博弈机制文档）：成员永久标签、不可删除。原因是成员在快件历史中全是纯文本名字引用（`task_owners.owner_name` / `tasks.requester` / `tasks.confirmed_by`），没有外键，硬删会留悬空标签、弄脏统计，且 `tasks.confirm` 要求签收人必须是 members 表内成员——删掉「有未签收快件的提出人」会让该快件永远无法签收。
- **决策（2026-09-07，产品拍板）：有守卫的硬删。** 零历史成员（手滑加错的）可删；有任何快件痕迹的成员拒绝删除并提示原因。不引入「停用」标记，不改表结构，不碰统计口径。

## 规则

1. **守卫三引用**：删除前按名字检查三类引用，任一命中即拒绝（TRPCError `CONFLICT`，中文提示列出各引用计数）：
   - `task_owners.owner_name`（当过负责人）
   - `tasks.requester`（提出过快件）
   - `tasks.confirmed_by`（签收过快件）
2. **零历史 → 硬删**：`runTx` 内删 `members` 行 + `appendAudit` 记一条删除日志（`entity: "member"`、`field: "*"`、`oldValue: name`、`newValue: null`，与 addMember 的「整行新增记 \*」对称）。审计链只追加，删除动作本身留痕，历史日志不重写。
3. **不删的东西**：审计链历史行（append-only，天然保留）；成员曾出现的统计快照语义不变（有历史的成员本来就删不掉，不存在「统计里消失的人」）。
4. 并发 TOCTOU（守卫查完到删除落库之间恰好有快件引用该名字）：遵循 v2.2 评审决议「并发 TOCTOU 明确不做」，不设防。
5. 审计日志 entity 类型集合不变（`member` 已在用）。

## 接口

- tRPC：`van.members.remove`，mutation。
  - 入参：`{ name: memberTag, actor?: string（软身份，同 actorField） }`——用名字而非 id：members.name 唯一，且全领域身份（负责人/提出人/签收人/审计/我是谁/统计区）本就是名字标签，UI 入口「成员运力」区也只持名字。
  - 出参：`Member[]`（删除后最新成员列表，与 add 一致）
  - 错误：`NOT_FOUND`（名字不存在）、`CONFLICT`（守卫命中，提示如 `成员「张三」已有快件记录（负责 2 件 / 提出 1 件 / 签收 0 件），不可删除`）。
- 数据层：`api/queries/van.ts` 新增 `removeMember(name, actor?)`，守卫查询在事务外（与 addMember 的重名预检同风格；并发 TOCTOU 遵循 v2.2 评审决议不设防），删除与审计同事务。
- 入参校验复用既有 `memberTag` / `actorField`，无新增校验面，不单独出 zod 测试（行为覆盖靠下方套件与 E2E）。

## UI

- 入口：看板页「成员运力」区每行尾部加「删除」按钮（`btn btn-danger text-xs`，与快件删除列同款）。
  （2026-09-07 注：随统计面板统一，入口随成员运力迁至统计面板「负责人」页签每行尾部，按钮与守卫行为不变。）
- 点击弹 `window.confirm`（与快件删除同模式），确认后调 `members.remove`，成功 `toast.success` + 刷新，失败 `toast.error`（守卫原因直接透出）。
- 若被删成员恰是当前「我是谁」（localStorage actor），同步清空为（未选择）。

## 测试与验收

- 单测（`van.write.suite.ts` 成员块新增，三方方言自动覆盖）：
  1. 零历史成员删除成功，成员列表不再含该名字，审计链多一条 member/\*/oldValue=名字 的删除记录；
  2. 当过负责人（task_owners 命中）→ CONFLICT 拒绝；
  3. 当过提出人（requester 命中，即使无负责人）→ CONFLICT 拒绝；
  4. 当过签收人（confirmed_by 命中）→ CONFLICT 拒绝；
  5. id 不存在 → NOT_FOUND。
- `api/vanRouter.test.ts`：`members.remove` 入参复用 `memberTag`/`actorField`，无新增校验面，不单独出 zod 测试（见上「接口」）。
- E2E（`board.spec.ts`）：编辑器新增成员 → 运力区删除 → 断言消失；对有记录成员发起删除 → 断言错误提示可见。
- 门禁：`npm test` / `npm run check` / `npm run lint` / `npx prettier --check .` / `npm run test:e2e` 全绿。

## 明确不做

- 不做软删/停用标记（active 列）——如有「离职成员从下拉消失」诉求另立项。
- 不清理审计链中的历史行。
- 不做批量删除。
