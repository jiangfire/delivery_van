## Mock 策略

### 数据库 Mock 模板

```typescript
import { vi, describe, it, expect, beforeEach } from "vitest";
import { getDb } from "./connection";

// Mock getDb
vi.mock("./connection", () => ({
  getDb: vi.fn(),
}));

describe("addMember", () => {
  const mockDb = {
    select: vi.fn().mockReturnThis(),
    from: vi.fn().mockReturnThis(),
    where: vi.fn().mockReturnThis(),
    limit: vi.fn().mockResolvedValue([]),
    insert: vi.fn().mockResolvedValue({}),
    update: vi.fn().mockReturnThis(),
    delete: vi.fn().mockReturnThis(),
  };

  beforeEach(() => {
    vi.clearAllMocks();
    (getDb as any).mockReturnValue(mockDb);
  });

  it("正常添加成员", async () => {
    mockDb.limit.mockResolvedValue([]); // 无重名
    mockDb.insert.mockResolvedValue({});

    const result = await addMember("张三", 5);
    expect(mockDb.insert).toHaveBeenCalled();
  });
});
```

### 事务 Mock 模板（carryOver）

```typescript
describe("carryOver", () => {
  it("事务中结转任务", async () => {
    const mockTx = {
      select: vi.fn().mockReturnThis(),
      from: vi.fn().mockReturnThis(),
      where: vi.fn().mockReturnThis(),
      limit: vi.fn().mockReturnThis(),
      all: vi.fn().mockReturnValue([]),
      insert: vi.fn().mockReturnThis(),
      run: vi.fn(),
    };

    mockDb.transaction.mockImplementation((fn) => fn(mockTx));

    await carryOver("DV2607A", "DV2607B");
    expect(mockTx.insert).toHaveBeenCalled();
  });
});
```

## 风险与注意事项

1. **Mock 复杂度**：`carryOver` 使用事务，mock 事务需要仔细设计
2. **Drizzle 查询构建**：Drizzle 的链式调用需要 mock 多层返回
3. **测试隔离**：每个测试用例需要清理 mock 状态
4. **真 DB 集成测试**（可选）：Phase 4 后可考虑添加使用内存 SQLite 的集成测试
